# 출장ON AI v0.8.1 — HWPX 사진 첨부·저장 안정화

기존 [파주길잡이](https://smile7962.github.io/paju-giljabi/)에 새 기능을 추가하는 개발 브랜치입니다.
Claude가 만든 원본 디자인 시안은 [design/claude-prototype.html](../design/claude-prototype.html)에 보존했습니다.

**코드 원칙:** 빌드 도구·서버·회원가입 없이 HTML / CSS / 순수 JavaScript로 구성합니다.

도로 주행시간은 OSRM 추정치이며 실시간 교통을 반영하지 않습니다. 길찾기 버튼에 사용하는 모바일 딥링크는 설치된 앱과 기종에 따라 동작 차이가 있습니다.

## 개발 중 PC 화면 실행

1. GitHub에서 `feature/trip-on-ai` 브랜치의 ZIP을 다운로드합니다.
2. 압축 해제 후 `v2/index.html`을 Chrome 또는 Edge에서 엽니다.
3. 예시 입력 또는 실제 **공개 가능한 테스트 주소**를 입력하고 `방문지 검색 및 경로계산`을 누릅니다.
4. 경로가 계산되면 `출장계획 확정 · QR`을 누릅니다.
5. 로컬 파일 실행 중에는 QR 생성이 제한됩니다. `이 브라우저에서 미리보기`를 누르면 모바일 현장 화면을 PC에서 체험할 수 있습니다.

## 실제 휴대폰 QR 테스트를 위한 배포

**현재 기본 GitHub Pages에는 기존 파주길잡이만 배포되어 있습니다.** `feature/trip-on-ai`의 `v2/`는 아직 배포되지 않았습니다.

휴대폰 테스트를 하려면 먼저 `v2/` 파일을 HTTPS 주소에 배포해야 합니다. 기존 사이트를 보존하려면 테스트를 마친 뒤 개발 브랜치의 `v2/` 폴더를 `main`에 병합하는 방식이 간단합니다. 그러면 다음 주소로 접근 가능합니다.

`https://smile7962.github.io/paju-giljabi/v2/`

**주의:** 이 주소는 `v2/`가 배포된 뒤에만 유효합니다. 배포 전 QR 스캔 테스트 성공을 주장하지 마세요. 원본 `index.html`은 변경하지 않습니다.

모바일에서는 `mobile.html#trip=...` 링크로 방문정보를 전달합니다. QR에는 방문지명과 좌표가 인코딩되어 있으며 암호화되지 않습니다. **민원인 이름·전화번호·비공개 현장정보를 넣지 마세요.**

## 사진과 이메일 전송

- 촬영/선택한 사진은 현재 선택한 출장지의 확정 계획주소에 연결됩니다. GPS를 이용해 파일명 주소를 만들지 않습니다.
- 예: `t-..._S01_문발동29-29_01.jpg`
- 사진은 모바일 기기의 브라우저 저장소(IndexedDB)에 저장됩니다. 외부 서버로 자동 업로드하지 않습니다.
- `사진 공유`는 기기의 공유 창을 여는 기능입니다. 이메일 전송은 사용자가 직접 완료해야 합니다.
- 사진 여러 장 공유가 불가능하면 사진마다 `파일 저장`을 이용하세요.
- 현장메모를 PC로 가져오려면 `출장기록 복사`로 텍스트를 복사하여 승인된 업무메일 등에 붙여넣으세요.
- 사진 저장소는 사용자가 브라우저 데이터 삭제를 하거나 기기가 저장공간을 회수하면 소실될 수 있습니다. **출장 종료 후 곧바로 허용된 방식으로 사진을 전송**해야 합니다.
- 브라우저/메일 앱에 따라 공유 시 첨부파일 이름이 바뀔 수 있으므로 PC에서 확인해야 합니다.

## v0.3 외부 내비게이션 연동 (2026-10-14)

- PC 출장계획 완료 후 **출장일정 각 방문지**에 카카오맵 길찾기·네이버지도 검색·T맵 휴대폰 QR 버튼을 제공합니다.
- PC에서 T맵 버튼을 누르면 전체 출장 QR에 **선택 방문지 식별자**를 덧붙여, 휴대폰에서 해당 방문지를 열 수 있습니다.
- 모바일에서 카카오맵은 공식 좌표 길찾기 웹 URL을 열고, 네이버지도는 공식 `nmap://navigation` 스킴, T맵은 `tmap://route` 스킴으로 목적지를 전달합니다.
- 사용자의 휴대폰에 앱이 설치되지 않았거나 웹브라우저가 외부 앱 호출을 차단하면 **모바일 화면에 표시되는 '웹 지도 열기'와 '앱 설치' 버튼을 직접 선택**합니다. 웹에서는 앱 실행 성공 여부를 정확히 감지할 수 없으므로 자동 성공 또는 자동 설치를 표시하지 않습니다.
- 네이버지도 **PC 웹은 장소검색 화면**으로 연결합니다. PC 웹에 좌표를 자동 주입하는 공식 문서화된 URL은 확인되지 않았으므로, PC 버튼에 '네이버 검색'이라고 구분했습니다.
- T맵의 **웹 대체 링크는 카카오맵 좌표 길찾기**입니다. T맵 공식 좌표 웹길찾기 규격이 확인되지 않았으므로 이를 T맵 경로인 것처럼 표시하지 않습니다.
- 예전에 계산한 경로의 주소·방문순서가 수정되면 이전 결과의 QR·인쇄·길찾기 버튼이 비활성화됩니다.
- `v2/nav.js`에서 외부 지도 링크를 관리하며, 복잡한 SDK나 추가 비밀키를 사용하지 않습니다.

**검증:** JavaScript 문법, 생성 URL 파라미터, iPhone/Android 스토어 연결 문자열 검증 완료. 실제 외부 앱 실행 및 대체 경로는 사용자 단말에서 확인 필요.

참고 공식 문서:
- 카카오맵 웹 길찾기: https://apis.map.kakao.com/web/guide/
- 네이버지도 앱 URL: https://guide.ncloud-docs.com/docs/ko/application-maps-url-scheme-vpc

## 인쇄 경로 잘림 수정 (2026-10-14)

PC의 `경로표 인쇄` 버튼은 이제 기존 지도 화면을 축소 인쇄하지 않고 **전용 `v2/print.html` A4 미리보기**를 새 탭으로 엽니다.

1. 출장지를 검색하고 **방문지 검색 및 경로계산**을 완료합니다.
2. **경로표 인쇄** 버튼을 누릅니다.
3. 새로 열린 A4 경로표에서 **파란 경로선과 모든 방문지 마커가 한 지도 안에 표시되는지** 확인합니다.
4. 지도 배경이 로딩된 후 **인쇄하기 / PDF 저장**을 누릅니다.

- 인쇄용 Leaflet 지도를 원래 PC 화면과 별개로 생성하고, 인쇄영역 전체 너비에 맞추어 `fitBounds`를 다시 실행합니다.
- 전체 경로선, 방문순서, 왕복 이동거리·시간, 모바일 QR을 한 문서로 표시합니다.
- 방문지가 많으면 방문목록은 여러 페이지로 이어질 수 있지만 **경로 지도 전체는 한 페이지에서 확인**합니다.
- 계산한 경로는 동일 출처의 브라우저 저장소에 인쇄를 위한 임시 데이터로 보관합니다. 1시간 후 출력에 사용하지 않습니다. **민감한 출장지·민원인 정보를 입력하지 마세요.**
- 브라우저에서 직접 Ctrl+P를 누르는 대신 앱의 **경로표 인쇄** 버튼을 사용하세요.

## v0.4 출장복명 기능 (2026-10-14)

1. PC에서 출장계획의 `출장계획 확정 · QR`을 눌러 해당 출장을 저장합니다.
2. 출장지별로 휴대폰에서 현장사진을 촬영하고 **사진 공유**를 이용해 허용된 이메일 등으로 사진 파일을 PC에 전달합니다.
3. 휴대폰의 **출장기록 복사** 내용을 이메일 본문 등으로 PC에 전달합니다.
4. PC에서 `출장복명 작성`을 눌러 `/v2/report.html`을 엽니다. 반드시 출장계획을 생성한 **같은 PC·같은 브라우저 프로필**이어야 합니다.
5. 오른쪽 `모바일 출장기록 가져오기` 입력창에 복사한 내용을 붙여넣고 `출장기록 적용`을 누릅니다.
6. 이메일로 받은 현장사진을 **사진 여러 장 선택**으로 불러옵니다.
7. `출장ID_S01_계획주소_01.jpg` 형식으로 **출장 ID + 방문지 ID + 계획주소**가 모두 일치할 때만 자동 분류됩니다. 다르게 저장된 사진은 수동 분류합니다.
8. 방문지별 현장확인내용·조치사항·사진설명을 수정하면 가운데 A4 문서가 즉시 갱신됩니다.
9. `인쇄 / PDF 저장`을 누르면 문서와 사진대지를 출력합니다.

### 제한사항 및 보안

- **실제 AI 연동 전:** 사용자 입력 사실만 서식에 배치합니다. AI가 사실을 임의 작성하지 않으며 문장 정리 기능은 다음 단계입니다.
- **서식은 시연용 기본 양식입니다.** 파주시 출장복명서 원본 서식(HWPX 등)을 제공받으면 반영합니다.
- 보고서 작성 중 메모는 PC localStorage에, 불러온 사진은 PC IndexedDB에 저장됩니다. 브라우저 데이터를 지우면 소실될 수 있습니다.
- 휴대폰 사진과 PC의 사진 저장소는 자동 동기화되지 않습니다. **이메일 등을 통한 사용자의 파일 전달이 반드시 필요합니다.**
- HEIC/HEIF 사진은 브라우저와 출력 기능의 지원 여부가 다릅니다. PDF에 넣으려면 JPEG 또는 PNG로 변환한 뒤 불러오세요.
- 같은 출장의 사진이더라도 이메일 앱이 파일명을 변경할 수 있습니다. 이 경우 **수동 분류**가 필요합니다.
- 사진을 외부 서버로 자동 업로드하거나 AI에 전달하지 않습니다. 개발/검증은 개인정보·비공개 민원사진을 제외한 모의자료로 진행하세요.
- 사진은 최대 60장, 한 파일당 25MB까지만 처리합니다. 대량 사진일 때 브라우저 저장공간과 인쇄 성능에 주의하세요.
- 여러 건을 관리하는 중앙 서버는 없습니다. 같은 브라우저에서 '가장 최근에 확정한 출장계획'을 기준으로 문서를 엽니다.
- 개인정보·보안 심사 없이 실제 행정업무 자료를 투입해서는 안 됩니다.

## v0.5 장소별 개별 출장결과보고서 (2026-10-15)

**변경 이유:** 여러 출장지를 하나의 보고서에 묶으면 추후 장소명·민원별 문서 검색이 어렵습니다. 이에 **하나의 출장계획에 여러 개의 독립된 결과보고서**를 연결합니다.

- 예: 3곳 출장 → 출장계획 1건 / 결과보고서 3건 / 각 장소 현장사진대지 별도 출력
- 왼쪽에서 출장장소를 선택하면 **중앙 A4 문서에는 해당 출장지만 표시**됩니다.
- 각 방문지는 독립된 출장일시·참석·현장 확인내용·조치사항·문서번호를 저장합니다.

## v0.6 원본 HWPX 서식 유지 및 온나라 파일 불러오기 준비 (2026-10-15)

**핵심 목표:** 사용자 PC에서 기존 **파주시 출장결과보고서.hwpx**를 선택하고, 선택한 출장장소의 내용만 원본 서식에 채운 HWPX를 내려받아 한글에서 검토한 뒤 온나라에서 파일 불러오기.

1. PC 출장계획을 확정하고 `출장결과보고서` 화면을 엽니다.
2. 좌측에서 **보고할 출장장소 1곳**을 선택합니다.
3. 오른쪽의 **원본 HWPX 서식**에서 사용자가 가진 **출장결과보고서.hwpx**를 선택합니다.
4. 출장자·일시·참석·현장 확인내용·조치사항 등을 작성합니다.
5. 중앙 문서에서 내용을 확인하고 **원본 HWPX로 저장**을 클릭합니다.
6. `출장결과보고서_날짜_장소명_장소ID_출장ID.hwpx` 파일이 내려받아집니다.
7. 내려받은 HWPX를 한글 프로그램으로 열어 표·내용·서식·줄바꿈을 점검하고, 필요하면 한글에서 다시 저장한 후 **온나라에서 파일을 불러오기** 합니다.
8. 다른 출장장소를 선택하면 원본 양식으로 별도의 HWPX를 생성합니다.

### 원본 보존 방식

- HWPX는 원본의 ZIP/XML 패키지입니다. 이 기능은 새 문서 서식을 만드는 것이 아니라 **원본 파일을 복사하여 본문 XML의 텍스트만 교체**합니다.
- `Contents/section0.xml`의 문서번호, 보고일자, 출장자, 제목의 출장목적, 개요(일시·장소·참석·내용)를 수정하며 다른 구성파일과 원본 결재란/표/스타일은 유지합니다.
- 문서 내 결재일자·공개여부 등 입력되지 않은 필드는 임의로 생성하지 않습니다.
- 원본 HWPX 파일은 **웹브라우저 메모리 안에서만 사용**합니다. 서버·GitHub·AI API에 올리지 않으며, 새로고침 후에는 다시 선택해야 합니다.
- 유효한 HWPX MIME/파일구조 및 제공된 출장결과보고서 원본 표 구조를 확인하고 다른 양식이면 출력하지 않습니다.
- `v2/hwpx.js`의 단일 모듈과 JSZip 라이브러리를 사용합니다. 템플릿 저장 기능, 별도 백엔드/로그인 시스템은 추가하지 않았습니다.

### 현재 한계 — 반드시 확인

- **v0.6 당시 한계였던 HWPX 사진 미삽입은 v0.8에서 개선했습니다.** JPG·PNG·WEBP로 분류된 사진은 원본 보고서 뒤에 자동 삽입합니다. 출력 후 한글에서 열리는지 반드시 확인해야 합니다.

## v0.7 — 온나라 기본 글씨 제거 + 현장메모 초안 작성 (2026-10-16)

### 1. 원본 HWPX 상단 빨간 글씨 공란

원본 `출장결과보고서.hwpx`에는 온나라에서 입력해야 하는 값 **`3년`**(보존기간 칸)과 **`건축신고3팀장`**(결재란 상단)이 기본으로 설정되어 있습니다. 이전 버전은 이를 그대로 내보냈으므로 두 텍스트가 나타났습니다.

- HWPX 생성 시 **상단 표의 해당 두 칸의 글자만 비웁니다.**
- 표의 크기·병합·선·글자 속성은 유지하며 `문서번호`, `보존기간`, `출장자` 등의 검은색 항목명도 유지합니다.
- 본문은 출장목적/일시/장소/참석/현장확인내용/실제 조치사항에 한해 입력합니다.
- 기타 온나라 관리 필드는 작성하지 않습니다.
- 예전 HWPX의 프리뷰 썸네일 캐시에는 원래 글씨가 남을 수 있어, **실제 한글 프로그램에서 열어 본문/상단 표를 확인**하세요.

### 2. 즉시 사용할 수 있는 로컬 문장 정리

현장확인내용 또는 실제 조치사항을 입력한 뒤 **현장메모 문장 정리 (로컬)** 버튼을 누릅니다.

- 불필요한 줄 앞 기호·공백을 정리하고 문장 끝 마침표를 보완합니다.
- 원본의 사실관계는 변경하지 않으며 내용이 없는 항목을 추측해서 채우지 않습니다.
- 결과는 **초안 미리보기**에 나타납니다. 사용자 검토·수정 → **확인 후 적용**을 누를 때만 현장내용에 반영합니다.
- 이 기능은 규칙 기반 문자열 정리이며 **생성형 AI가 아닙니다**. 오프라인에서 작동합니다.

### 3. 생성형 AI 초안 — 프록시 연결 시만 사용 가능

UI의 **생성형 AI 초안 요청** 기능은 `v2/worker/ai-draft.js`에 포함된 서버 측 프록시 예제를 별도 배포한 뒤, 승인된 HTTPS **`/draft`** 주소를 지정해야 작동합니다. **현재 저장소/Pages 배포만으로 Gemini API에 연결되지 않습니다.**

- AI 키는 서버 측 `GEMINI_API_KEY` 비밀 환경변수로 관리합니다. 웹앱에 비밀키를 넣지 않습니다.
- 명시적으로 AI 요청 버튼을 누르고 데이터 전송 여부를 확인한 경우에만 `장소·시간·참석·출장목적·현장확인내용·조치사항` 텍스트를 전송합니다.
- 사진·원본 HWPX·다른 출장지 기록은 전송하지 않습니다.
- 모델에는 입력된 사실만 공문서체로 정리하고 새로운 사실·조치결과를 만들지 말도록 지시합니다. **AI 생성문구를 그대로 신뢰하지 말고 담당자가 대조·수정**합니다.
- 입력내용을 수정하거나 출장지를 바꾸면 아직 적용하지 않은 초안은 폐기합니다.
- 프록시 예제는 프로토타입 참고용입니다. **CORS만으로 인증·오남용을 막을 수 없으므로 기관 보안검토, 인증, 접근제한, 사용량 제한 없이 공용 인터넷에 배포하지 마세요.** 서비스 공급자의 데이터 처리·학습·보존 정책도 별도로 확인해야 합니다.
- 실제 민원인·비공개 현장정보는 공개 AI 서비스로 전송하지 마세요. 대회 시연은 **합성데이터만** 사용합니다.

### 4. 이번 변경 파일

`v2/hwpx.js`, `v2/report.html`, `v2/report.js`, `v2/report.css`, `v2/draft.js`, `v2/worker/ai-draft.js`와 이 README입니다. 기존 파주길잡이 `index.html`은 변경하지 않습니다.

- JPG·PNG·WEBP를 브라우저 안에서 JPEG(긴 변 최대 1600px, 품질 약 80%)로 변환합니다.
- HWPX의 `BinData/` JPEG 실파일, `Contents/content.hpf` 이미지 manifest, `Contents/section0.xml` 그림 문단을 연결해 저장합니다.
- **출장장소당 1~12장**을 첨부할 수 있습니다. 한 사진당 별도 페이지를 사용하여 복명 문서의 레이아웃 안정성을 우선합니다.
- 사진 설명은 파일별 입력된 캡션을 사용하며, 없으면 `현장사진`으로 표시합니다.
- 해당 출장장소의 사진만 포함합니다. 미분류 사진이나 다른 방문지 사진을 임의 포함하지 않습니다.
- HEIC·HEIF는 이 버전에서 HWPX 삽입 불가합니다. JPEG로 변환 후 다시 등록하거나 해당 사진을 제거해야 출력할 수 있습니다.
- 사진 원본 및 HWPX는 외부 서버/AI 모델에 전송하지 않습니다. 사진 압축·포함·파일 저장은 PC 브라우저에서 이루어집니다.
- **사진 없는 HWPX는 종전 방식대로 생성됩니다.**
- 새 문서의 한글 실제 화면 및 온나라 파일불러오기는 사용자 PC에서 **추가 검증 필요**합니다. ZIP·XML 구문 및 사진 참조 구조의 검증만으로 한글 호환성을 보장하지 않습니다.
- 제공받은 원본 HWPX는 GitHub에 업로드하지 않습니다. 모의 사진과 시험 HWPX도 개발 참고자료이며 실제 민원정보를 포함하지 않습니다.

### 시험 결과

- 원본 HWPX를 기준으로 모의 JPEG 1장 추가 시 ZIP 무결성 확인, `content.hpf` 이미지 등록과 `section0.xml` 그림 참조 연결, 본문 원래 텍스트 및 `header.xml` 서식 보존을 검사했습니다.
- 검증용 파일 `출장결과보고서_사진자동첨부_모의테스트.hwpx`는 ChatGPT 대화 첨부로 제공하며 공개 저장소에는 넣지 않습니다.

## v0.8.1 — HWPX 저장 실패 보완 (2026-10-16)

현장사진이 PC 화면에 표시되지만 **원본 HWPX로 저장** 시 파일이 내려받아지지 않는 문제를 조사해 오류 판별·저장 경로를 보완했습니다.

- **사진 판독 보완:** 이메일 첨부파일은 JPG/PNG/WebP 이름이라도 브라우저 MIME 정보가 비어 있는 경우가 있습니다. 사진 바이트의 실제 JPEG/PNG/WebP 형식을 확인하고 디코딩할 수 있으면 JPEG로 변환합니다.
- **진행상태 표시:** 원본 읽기 → 본문 입력 → 사진 1/전체 변환 → HWPX 압축 → 생성 완료를 저장 버튼 바로 아래에 표시합니다.
- **오류 표시:** 생성에 실패하면 실패 단계·원인을 빨간 안내문으로 표시합니다. 오류를 확인하기 위해 개발자 도구가 필수는 아닙니다.
- **수동 다운로드:** 브라우저가 비동기 생성 후 자동 다운로드를 차단할 경우 **HWPX 직접 다운로드** 링크가 나타납니다. 그 링크를 클릭해 저장합니다. 이미 만들어진 파일은 현재 페이지에만 유지됩니다.
- **문제 분리:** 오른쪽 원본 HWPX 선택란 아래 **'분류된 현장사진을 HWPX 붙임에 포함'** 체크를 해제하면 본문만 생성할 수 있습니다. 사진 첨부가 실패해도 기존 본문작성 기능이 가능한지 확인하는 진단용입니다.
- 원본 결재표의 온나라 관리정보 처리·출장지별 개별 보고·사진 분류 규칙은 변경하지 않았습니다.

**검증:** JavaScript 구문 검사, 사진 헤더가 정상이나 MIME 문자열이 비어 있는 모의 JPEG 판독 성공, 이미지가 아닌 바이트 거부 확인. 실제 사용자 브라우저에서의 파일 다운로드 및 생성 HWPX의 한글·온나라 호환성은 다시 확인이 필요합니다.

### 테스트 순서

1. 출장ON AI `/v2/report.html`에서 **Ctrl+F5**로 새로고침합니다.
2. 원본 `출장결과보고서.hwpx`(이전에 작성한 결과보고서가 아닌 **빈 원본**)를 선택합니다.
3. 현장사진을 해당 방문지에 분류했는지 확인한 뒤 **원본 HWPX로 저장**을 누릅니다.
4. 버튼 바로 아래 생성단계 또는 오류 메시지를 확인합니다.
5. 완료됐지만 파일이 없으면 **HWPX 직접 다운로드**를 클릭합니다.
6. 실패한 경우 **분류된 현장사진을 HWPX 붙임에 포함**을 해제하고 다시 눌러 본문만 저장되는지 확인합니다.
7. 여전히 실패하면 **빨간 오류 메시지 전체**를 공유하여 원인을 확인합니다.
